When queues can grow, provide backpressure.

When retries occur, understand idempotency.

When workers can fail, define recovery.

When shutdown occurs, coordinate lifecycle.

When deterministic output matters, isolate nondeterministic scheduling from observable results.

Correct concurrent software does not depend on luck.

Correct concurrent software does not depend on one observed execution order.

Correct concurrent software establishes the relationships required for correctness explicitly.

Concurrency is controlled overlap of work.

Synchronization establishes required relationships between that work.
