Summary

A method and historical Module Creation Request is established to provide the basic module creation concept and historical fact of the module's request.

Any new module requires an MCR. Bug fixes, maintenance changes, and ordinary revisions to an existing module do not.

The requester must be ready to explain the module's concept and reason for creation as a separate step after submission.

Applicability

The MCR requirement applies regardless of organizational position or authority. The founder submitted the first MCR under this policy; therefore, no organizational role is exempt from the requirement.

The first MCR is preserved as institutional history demonstrating that the policy applied to its author from its first use.

Governance Boundary

Approval of an MCR authorizes the module creation process but remains distinct from module qualification and activation.

Permission to create a module is not evidence that the resulting module is trusted.

MCR approval authorizes module creation but does not override system qualification requirements.

Module development will not begin until the target system Core has successfully completed all mandatory Core qualification tests and reached QUALIFIED status.

This establishes two separate gates:

Gate 1 — Authorization: Approved MCR.

Gate 2 — Eligibility: Qualified system Core.

Passing one gate does not satisfy the other.
