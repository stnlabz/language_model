Input validation is the process of determining whether supplied data satisfies the requirements defined for that input.

Applications receive input from many sources.

Examples include:

HTML forms.

URLs.

Query parameters.

HTTP headers.

Cookies.

JSON requests.

XML requests.

API clients.

Command-line arguments.

Configuration files.

Environment variables.

Uploaded files.

Databases.

Message queues.

Network protocols.

Other applications.

Hardware devices.

Users.

Do not assume input is trustworthy because it came from a familiar source.

Input crossing a trust boundary must be treated according to the receiving system's requirements.

A trust boundary is a point where data moves between components or contexts with different trust assumptions.

Examples include:

Browser to server.

Client application to API.

Internet to application.

Application to database.

Plugin to host application.

External service to internal service.

Configuration file to privileged process.

Message queue to worker.

User-controlled file to parser.

Do not trust data merely because it is inside the application now.

Its origin still matters.

Input validation answers:

Does this input satisfy the requirements for this field or operation?

Validation does not answer:

Is this user authorized?

Is this input safe in every possible output context?

Is this data true?

Is this data trustworthy?

Is this request legitimate?

Keep these questions separate.

Valid input can still be unauthorized.

Valid input can still be malicious in another context.

Valid input can still be factually false.

Valid input can still violate a business rule.

Validation establishes conformance to defined input requirements.

Identify the expected input.

Define its allowed values.

Define its range where applicable.

Define whether it is required.

Define any structural relationships.

Parse it.

Validate it.

Reject it if the requirements are not satisfied.
