A JSON file can be better for small configuration.
A relational database can be better for structured concurrent records.
An append-only text file can be appropriate for simple logs.
A binary format can be appropriate for compact protocol data.
Persistence mechanisms should be chosen deliberately.
SQL is powerful because relational operations can express relationships directly.
Power does not require unnecessary complexity.
A small schema can be correct.
A small query can be correct.
A small database can be useful.
A database with one table is still a database.
A relational database should not be expanded merely to appear sophisticated.
Schema complexity should follow actual relationships.
Indexes should follow actual queries.
Transactions should follow actual atomicity requirements.
Constraints should follow actual integrity requirements.
Permissions should follow actual authority.
Database engineering should remain evidence-driven.
Measure query behavior before optimizing.
Inspect execution plans before guessing.
Verify constraints rather than assuming application code enforced them.
Verify transaction boundaries rather than assuming atomicity.
Verify permissions using the actual database account.
Verify connectivity using the actual application environment.
Verify database version before assuming feature support.
Verify backup restoration rather than assuming backup success.
Verify affected rows rather than assuming modification.
Verify commit success rather than assuming persistence.
A database returning zero rows is evidence of an empty result for that query.
It is not evidence that the database has nothing in it.
It is not evidence that the database is broken.
It is not evidence that the network is broken.
It is not evidence that an internal service is unavailable.
The meaning of zero rows depends on the query.
A query asks a specific question of stored data.
A correct answer can be empty.
A database error is not an answer to the query.
A database timeout is not an empty answer.
A database connection failure is not an empty answer.
A permission failure is not an empty answer.
A syntax failure is not an empty answer.
A constraint failure is not an empty answer.
Precise failure classification is part of correct database engineering.
SQL provides a structured language for relational data.
The database provides storage, integrity mechanisms, concurrency control, and query execution.
The application provides domain behavior.
Security provides authority boundaries.
Networking provides communication when the database is remote.
The operating system provides the execution environment.
Each layer has a defined responsibility.
Correct systems preserve those boundaries.
