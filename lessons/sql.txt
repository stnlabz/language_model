An authoritative declaration should be preferred over inference from unrelated historical records when the data model defines that authority.
Evidence retrieval and evidence interpretation are separate operations.
A database can return relevant evidence without that evidence supporting the requested conclusion.
Correct SQL retrieval does not guarantee correct reasoning about the retrieved rows.
A query can be syntactically valid and semantically wrong.
A query can be semantically correct and operationally inefficient.
A query can be efficient and still violate authorization.
A secure query can still answer the wrong question.
Database engineering requires correctness, integrity, security, performance, recoverability, and understandable behavior.
Simple schemas are easier to reason about when they satisfy the requirements.
Explicit constraints are preferable to undocumented assumptions.
Explicit ordering is preferable when deterministic ordering matters.
Explicit transactions are preferable when multiple writes must succeed or fail as a unit.
Explicit error handling is preferable to silently discarding database failures.
Parameterized queries are preferable to constructing SQL by concatenating untrusted data.
Measured query plans are preferable to guessing about performance.
Tested backups are preferable to assuming backups work.
Defined ownership of schema changes is preferable to uncontrolled production modification.
A relational database is a persistent system of record only when the architecture assigns it that authority.
SQL is a tool for expressing operations over relational data.
Correct use of SQL requires understanding both the query language and the database system executing it.
